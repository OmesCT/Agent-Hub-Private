**The real AAA DEV (read-only discovery GETs, 2026-10-05):** Duende IdentityServer; issuer https://auth-dev.tcrbank.com (also served from auth-dev.thaicreditbank.com, same issuer, so MetadataAddress stays empty); PKCE S256, client_secret_post/basic, RS256; it advertises **PAR** (`/connect/par`, not required) and ASP.NET Core 10 uses it by itself, so /auth/login needs the REAL client secret and egress to the AAA host on every login, and scope/redirect_uri/secret errors show up at /auth/login. `scopes_supported` has openid profile email roles application application_profile groups offline_access and many `sams.*` but NOT plain `sams` (the committed scope list has it: if AAA says invalid_scope blank Authentication__Aaa__Scopes__4, and __5 for offline_access). `claims_supported` has `role`, `application_role`, `user_group`, `department_id` but NOT `roles` or `team_code`; FITs needs a single `team_code` or it answers 401, so invalid_team_code is the likely first real failure.

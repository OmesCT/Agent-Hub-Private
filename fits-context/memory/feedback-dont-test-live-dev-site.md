On 2026-10-05, once https://fits.dev.tcbank.local/ was up, the user asked whether bugs were likely and said not to test that site but to "try other ways that do not affect the web": no browsing, no API calls, no logins, no writes against it.

**Why:** it is the shared DEV deployment the team is bringing up; mock sign-in there lets anyone act as any user, and test writes would leave junk in its database.

**How to apply:** find deployment bugs offline: read the code and configs, scan the built image, and run the same images as a local replica (recipe in [[reference-run-fits-locally]], "OCP-like replica"). Report what was and was not covered (Kong, Route, Vault, real node sizing cannot be replicated). Pod metrics and logs in the OCP console are fine for the user to read; they do not touch the app. Narrow exception, same day: the user created one test item on the DEV site themselves and asked me to look whether it reached the database. I answered with a single read-only GET of `/api/items/all` using the Development header `X-User-Name: admin` (TLS verified, no -k), no writes, no browser login, and said exactly what I had requested. Only do such a look when the user asks for it explicitly, and keep it to reads.

Lifted for one request, later on 2026-10-05: "ตอนนี้เรา online fits ขึ้น ocp แล้ว ลองเข้าไปทดสอบหน่อย https://fits.dev.tcbank.local/".

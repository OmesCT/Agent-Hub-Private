Verified 2026-10-03 on 0.18.0. From the repo root:

`PORT=127.0.0.1:8080 API_PORT=5051 docker compose up -d --build web`

This starts postgres + attachments-perms + api + web (builds fits-api / fits-web, overwriting the old :latest images). Open http://127.0.0.1:8080 (Browser pane works; set the viewport to 1440x900, the pane is only ~800px wide and collapses the sidebar).

Updating to a new release (done 2026-10-05, 0.18.0 -> 0.19.0): `git fetch` (needs the VPN: with it off, GitLab DNS times out and `glab` fails too), `git merge --ff-only origin/main` on dev-ohm, check `git diff --name-only <old> HEAD` for migrations and dependency files, then run the same compose command again; the image rebuild took about a minute and the fits-postgres data (27 items) survived. A new Browser-pane tab starts signed out; click targets by ref (`find`) when the screenshot frame changes size.

From a git worktree (2026-10-06, 0.19.1): the compose file fixes container names (`fits-web`, `fits-api`, `fits-postgres`) and the running stack's project is `fits`, so inside the worktree `PORT=127.0.0.1:8080 API_PORT=5051 docker compose -p fits -f docker-compose.yml up -d --build --no-deps web` replaces only the web container, builds from the worktree and leaves api and postgres (and the data) alone. No `.env` exists (only `.env.example`), the defaults apply. The web bundle name changes per version (0.19.1 mock build: `index-B7SKRScA.js`; DEV's SSO build has another hash).

Traps:
- Name the service (`up … web`), not plain `up`: `api-tests` has no profile and would build and run the whole test suite.
- :5050 (default API_PORT) is held by an unrelated long-running `IT.Budget.Api` from ~/workspace/IT_Budget_Management_Test_Package_1 (running since Sep 16). Do not kill it; use API_PORT=5051. vite.config.ts hard-codes its proxy to localhost:5050, so a Vite dev server would talk to that old API, not FITs.
- Never build the compose `web` with VITE_ENABLE_DEV_AUTH=true: `api/client.ts:91` throws in a production bundle, so the page is blank. The persona dropdown (`#roleSelect`) exists only under `VITE_ENABLE_DEV_AUTH=true vite` (dev server). Compose builds use mock login instead.
- Compose publishes web on 0.0.0.0:8080 by default; `PORT=127.0.0.1:8080` keeps it loopback-only (the API runs Development and trusts X-User-Name).
- Postgres data sits in an anonymous volume of container fits-postgres. `docker compose stop` keeps it; `docker compose down` orphans it (next `up` starts an empty DB). Data found on 2026-10-03: 27 items (12 are 26DEM demo rows), 7 POs, FY2026 cut already committed 2026-10-02, so scripts/demo-seed.sh was not needed.
- Do not run scripts/capture_screenshots.py: it overwrites tracked pictures in docs/assets from the mockup.

Mock login: usernames come from database/seeds/development-users.json: admin (ADMIN), chris and infrahead (DEPTHEAD, INFRA), priya (REQUESTER), cio, auditor, proc. The form only checks the password is non-empty and never sends it. Use the dummy value the e2e fixtures use (frontend/e2e/helpers.ts), never a real password. Signing out and in as another user keeps the previous user's view (K14 in #136).

Verification techniques that worked (2026-10-03, re-checking #136 items on 0.18.0):
- Failure injection in the live app without touching the server: in the Browser pane run JS that wraps `window.fetch` to answer 500/403 for chosen GET patterns and to block every non-GET `/api/` call (so nothing can reach the DB); it survives sign-out/in but not a page reload. Do NOT then click approval or send-back confirm buttons in the live app: the auto-mode classifier denied the approve confirm even with POSTs blocked, and a denial must not be worked around. Use vitest with a stubbed `fetch` for those paths (pattern: copy the header of frontend/src/shell/FitsShell.test.tsx; test ids `approve-confirm-confirm`, `sendback-modal`, `sendback-confirm`, `approval-outcome-failed-<bgid>`), put temporary tests in frontend/src/__bugverify__/ and delete them after.
- Layout: emulate 390x844 with resize_window and read `documentElement.scrollWidth` vs `clientWidth` through the JS tool; the 800px pane otherwise collapses the sidebar. Reset with preset "desktop" at the end.
- Shell gotchas: macOS has no `timeout`; the Bash tool keeps the cwd between calls, so `cd x && cmd` drifts into subfolders and OMC hooks then create stray ignored `.omc/` dirs there (use `( cd x && cmd )`); unquoted `--include=*.cs` fails in zsh.
- The sub-agent alias `opus` resolves to a model this account cannot use (404 model_not_found; seen again on 2026-10-06, all 4 reviewers died within seconds); pass `model: "sonnet"` (Sonnet 5.5 ran 25-35 minute read-only code reviews of about 600k tokens each). A running agent can be told to wrap up with SendMessage (queued for its next tool round).
- A sub-agent that uses `mcp__Claude_Browser__*` drives the SAME default Browser tab as the main session (2026-10-06: the shell reviewer navigated my tab to http://localhost:8080 and toggled the language mid-script). Tell reviewers not to use the browser, or to open their own tab. sessionStorage is per origin: 127.0.0.1 and localhost are different sessions.
- `npm run build` runs `tsc --noEmit` against the ROOT `tsconfig.json` (strict, DOM.Iterable) and is clean on 0.19.1; `tsc -p tsconfig.app.json` reports 14 errors (unused symbols, erasableSyntaxOnly) but that file is a Vite-template leftover, not a gate. Run vitest in a worktree by symlinking `frontend/node_modules` from the main checkout (53 files / 536 tests on 0.19.1, 22 s) and remove the symlink afterwards: git does not ignore a symlink.
- Mount-time failure test (2026-10-06, #158 M3): patch `window.fetch` (500 for one GET pattern, 503 for every non-GET), sign out and in again WITHOUT reloading, open the view; a reload restores the real fetch. Confirm sheets (approve, sign-off), the Send Back dialog and the Create form can be opened and cancelled safely; never press their confirm buttons.
- Browser tool coordinates: `computer` clicks with `coordinate` use the screenshot frame (800x500 for a 1440x900 viewport), `ref` clicks use page pixels. Admin layout at 1440x900: sidebar x=79, y=172 register, 200 approvals, 228 reallocation, 256 PO, 311 audit, 340 settings, 367 help; stable selectors are `[data-testid="canvas-nav-<view>"]`, `#langToggle`, `#roleLabel`, `#profileBtn` (it only opens Settings).

OCP-like replica (done 2026-10-05, no contact with the DEV site; scripts were throwaway in the session scratchpad): own docker network + `postgres:16-alpine` on `--tmpfs /var/lib/postgresql/data` (EMPTY database); API = `fits-api:latest` with `--user 1000680000:1000680000 --read-only --tmpfs /tmp --cap-drop ALL --security-opt no-new-privileges --memory 384m --memory-swap 384m -e TZ=Asia/Bangkok -e ASPNETCORE_ENVIRONMENT=Development -e ConnectionStrings__BudgetDb=... -e Authentication__Authority= -e Authentication__Audience= -v database/seeds:/app/seeds:ro --network-alias fits-api-service`; web = `fits-web:latest` with the same flags, `--network-alias frontend-service`, `-p 127.0.0.1:5098:8080`; drive it with python http.client and `X-User-Name`. Ready in about 10 s. Results on 0.19.0 / alpha03 code: no 5xx on 22 page-load GETs x 7 personas with an empty DB; the full chain (priya submit, chris approve, admin approve, cio decide, sign-off, exports) works; PO booking answers 409 until the Stage 5 cut is committed (by design); attachment upload gives 500 on the read-only root (#129) and works with `Attachments__StoragePath=/tmp/attachments`; nginx passes a 3 MiB body, answers 413 above 26m, SignalR negotiate 200 and WebSocket 101; index.html has no Cache-Control and missing assets return index.html with 200 (R1-security-5 in #136); the API sat at 367-374 MiB of 384 MiB after a light run (#132). The browser pass on the replica showed no console errors and no NaN/undefined on the 8 admin views and the cio queue; a view stays selected across a persona switch (K14 in #136).

Running the test suites on this Mac (done 2026-10-05, dev-ohm eeb4e4a, nothing touches the compose stack):
- Backend needs a LIVE PostgreSQL (BudgetTestDatabase creates and drops a database per test class; env `ConnectionStrings__BudgetDb`, its Database name is ignored). Throwaway server: `docker run -d --name fits-flowtest-db -p 127.0.0.1:55432:5432 -e POSTGRES_PASSWORD=probe --tmpfs /var/lib/postgresql/data postgres:16-alpine -c fsync=off -c synchronous_commit=off -c max_connections=400`, then `( cd backend && ConnectionStrings__BudgetDb='Host=127.0.0.1;Port=55432;Database=postgres;Username=postgres;Password=probe' Attachments__StoragePath=<writable dir> dotnet test Fits.Tests/Fits.Tests.csproj )` (dotnet 10.0.107 is installed; 820 tests took 1m46s). Without `Attachments__StoragePath` two attachment tests (AttachmentHttpTests, AttachmentJourneyE2E) answer 500 because `/app/attachments` cannot be created on macOS; that is the environment, not a bug (same cause as #129 on OCP).
- The repo's CI-style route also works: `docker build -f backend/Fits.Tests/Dockerfile -t fits-api-tests:flowcheck backend`, then `docker run --rm -e "ConnectionStrings__BudgetDb=Host=<container IP of the throwaway postgres>;Port=5432;Database=postgres;Username=postgres;Password=probe" -v <dir>:/results fits-api-tests:flowcheck --logger "trx;LogFileName=x.trx" --results-directory /results` (the ENTRYPOINT is `dotnet test ... --no-build`, extra args are appended, so `--filter` works). IP: `docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' <name>` (the old `.NetworkSettings.IPAddress` template fails on Docker 29). Whole suite 981/981 in 1.5 min. Do not use `docker compose run api-tests`: it would use the compose `fits-postgres` of the user's own stack.
- Frontend: `( cd frontend && npx vitest run --exclude 'src/__bugverify__/**' )`: 580 tests (536 + 44 new); the untracked `src/__bugverify__/R3-session-3/5-repro` files fail on purpose (they reproduce open #136 bugs). `npx tsc --noEmit` also covers the test files.
- Playwright e2e (76 specs) is not run: `playwright.config.ts` hard-codes baseURL localhost:8080 and channel chrome, and some specs need the dev-auth Vite bundle (`#roleSelect`) while others need the production login form.
- Sensitivity check technique: patch one production rule at a time in a python script (assert the pattern occurs once, backup the file, `dotnet build`, `dotnet test --no-build --filter`, restore in `finally`, confirm with `git status`), compare the new tests against the old suite. All 5 flow breaks tried were caught by both.
- Shell traps again: the Bash tool keeps the cwd, so a bare `cd x && cmd` drifts (use `( cd x && cmd )`); foreground `sleep` is blocked (use run_in_background); BSD sed has no `\s`; the system python3 is 3.9 (no backslash in f-string expressions, no `str | None`), use `~/.local/bin/python3.11`.
